## Existing overlap and ranked hypotheses
1. PP transfer amortization and staging capacity. QEngine uses larger PP chunks and lends staging storage back to expert cache. Strata already has streaming expert batches, tunable pinned rings, cache borrowing and adaptive cache behavior. First measure actual capacities, cold-expert transfer bytes and synchronization. Screen existing ring sizing at fixed 4096 chunk before larger chunks. A 384-to-512 ring may hurt the MMQ path, so a negative is useful.
2. Larger PP chunks with safe scratch/cache lifetime. Compare 4096 and 8192 only after memory bounds and reachable gfx906 path are established. Strata HC/KV borrowing already exists; do not duplicate it. CUDA virtual-memory mapping is not a portable implementation.
3. Draft-only vocabulary shortlist with full verifier. Determine whether this is already covered by current MTP head binding/selection. Keep verifier full and treat numerical/quality changes separately. Profile before implementation.
4. Suffix lookup drafting. Existing suffix drafting, lookup chains and adaptive MTP make a generic port redundant. Investigate only a demonstrated missing mechanism.
5. Sparse-attention union inflation fallback. Establish reachability in this model and gfx906 path before considering any experiment. Do not conflate approximate sparse attention with an exact optimization.

## Experiment protocol
- Freeze the current model files, binary/configuration and new research source identity. Production-as-is and exactness controls are distinct profiles; current tail skipping must be reported explicitly.
- One GPU owner and one active experiment at a time. Keep artifacts and logs on remote storage.
- Cheapest falsification first: source reachability, CPU/component tests, short GPU smoke, then cold 65536-token PP with 1024 and 4096 output tokens. Include shorter context when diagnosing a mechanism.
- Record PP, TG, TTFT, complete request time, actual input/output token counts and IDs, cache capacity, memory, copy/stall counters and failures. Memory savings are not speed gains.
- Compare matched outputs/work. Report any divergence; do not promote a faster but different-output run as exact.
- Repeat promising gains with order reversal/matched controls, including combined candidates. Tiny single-pair differences are noise until repeated. Preserve regressions and every failed attempt.
- Keep old deployment rollback intact. No automatic production restore between experiments while this R&D request is active; restore only for a new user instruction or necessary safety recovery.
